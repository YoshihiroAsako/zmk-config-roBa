# 新しいチャットへの引継ぎ

AGENTS.md §8 に基づき移行を提案するときだけ読む。コンテキストの残量とサブスクの利用残量は別の情報として扱う。

## 提案から再開まで

1. 移行の理由を短く示す。残量を取得できない場合は数値を推測せず、工程の区切りや前提の混同など観測した理由を使う。同じ作業を十分継続できるなら移行を強制しない。
2. `nextaction-update` の手順で状態・履歴を保存し、差分を確認する。書込みできなかった内容はプロンプトに含める。
3. 下の型を実際のパス・判断・結果で埋め、コードブロックとして提示する。ユーザーに空欄を補わせず、未取得の情報は「未取得」と書く。秘密情報は含めない。
4. ユーザーの操作は「同じリポジトリで新しいチャットを開く → 選択可能なら推奨モデル・エフォートを設定 → プロンプト全体を貼って送信」の順で具体的に示す。画面名が未確認なら架空のボタンやメニューを案内しない。
5. 移行先ではファイルと作業状態を照合し、完了工程を重複実行しない。許可済みの範囲から再開し、新しい判断だけ選択式で確認する。

## 再開プロンプトの型

```text
作業場所: <リポジトリの絶対パス>
<作業名> を再開してください。

この作業場所の AGENTS.md と NextAction.md（代替指定があればそのファイル）を読み、
<設計書・必要な節> を確認してください。Archive は必要な項目だけ参照してください。

目的: <達成する状態>
完了済みと検証: <成果・確認済みの結果・未検証の区別>
承認済み: <ユーザー指示と対象・操作・方針の範囲>
未承認・未決: <判断が必要な事項、なければ「なし」>
作業途中: <変更ファイル・未コミット状態・保護する別件変更>
最初に行うこと: <具体的な一手>
完了条件: <必要な検証と期待結果>
推奨モデル / エフォート: <候補・利用可能性・理由>
サブスク残量: <枠別の取得値・取得日時・リセット時刻、または「未取得」>
未保存の内容: <保存失敗した内容、なければ「なし」>

実ファイルとこの記録を照合し、承認済み範囲の作業を検証・記録まで進めてください。
新しい判断が必要な場合は、推奨を先頭に選択肢と理由を提示してください。
```

AGENTS.common.md を直接使う原本リポジトリなどでは、型の参照先を実際の配置へ置き換える。引継ぎは新しい作業や外部操作の許可を追加しない。
