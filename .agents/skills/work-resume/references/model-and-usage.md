# モデル推奨・利用残量の詳細

正本は各リポジトリの `AGENTS.md` §8。この文書は `work-resume` の詳細な手順で、矛盾したら正本を優先する。

## モデル推奨と利用残量の細則(AGENTS.md §8)

新しい依頼で §8 の予定を示すときも、この細則に従う。

- 推奨の起点: 軽微な整理は軽量モデル / low、通常の実装・設計は標準モデル / medium。難度・検証結果に応じて上げる。「軽量モデル」「標準モデル」は選定基準であり、切替先のモデル名ではない。回答では実際に選べると確認できたモデルの具体名とエフォートを示す。候補の具体名を確認できなければ「具体名は未確認」と明記し、抽象名を切替先として提示しない。ユーザーの指定を優先し、API 価格をサブスクの消費率に換算しない。
- 現在値として扱うのは、この会話で確認できた値だけ(システムが示すモデル名、会話中の `/model`・`/effort` の結果など)。設定ファイル(`~/.claude/settings.json` 等)の既定値は「設定ファイル上は ◯◯(この会話での値は未取得)」と参考として示し、現在値とみなさない。
- 次の作業の案を示すときは、推奨・現在値・作業の大きさ・着手してよいか(切替はユーザーに任せる)を、案の選択と同じ質問に入れる。照合だけの往復を作らない。
- モデルとエフォートを示すときは、作業の大きさを「軽い」「中程度」「重い」のいずれかで同じ行に示す。大きさは、対象・探索・反復の量から見積もる。
- 長い作業の開始前と主要な工程の切替時に、取得できる利用残量とリセット時刻を確かめる。短時間枠と週間枠などを区別し、取得日時を添える。
- 警告は、残量を読めたときだけ出す(公式の閾値ではない)。適用される枠のどれかが 20% 以下で中〜重い作業、10% 以下で新しい作業。実績やサービスの警告から懸念があれば早めに知らせ、残量・予定の作業・理由と、分割 / 軽量化 / リセット後の再開を推奨付きで示す。完遂を保証しない。
- 読めなければ「未取得」とし、警告は出さない。推測しない。重い作業なら、その作業につき一度だけ表示値の共有を頼む。回答がなければ工程ごとに催促せず、承認済みの作業を保存できる単位で進める。必須の検証は省かない。追加課金や別の AI への無断の切替、常時監視の約束はしない。
