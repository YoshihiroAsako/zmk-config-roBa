# work-resume

作業の再開時に次の作業と設定を照合する手順。設定に差があれば、ユーザーは提示を見て切り替え、そのあと回答できる。正本は各リポジトリの `AGENTS.md`(§1 状態記録・§2 承認・§7 選択式・§8 モデル推奨)で、矛盾したらそちらが優先する。

## 前提

- 起動条件: 定型句「作業を再開します」「作業再開」「作業を再開して」、`/work-resume`、または同じ趣旨の言い換え(「作業を再開してください」「再開しましょう」「続きから始めます」等)。文言の完全一致は求めない。
- 起動しない場合:
  - 新チャットへの引継ぎプロンプト(`nextaction-update/references/handoff.md` の型)が貼られたとき。プロンプトの指示に従う。
  - 「作業を再開して、◯◯をやって」のように着手内容を具体的に指示されたとき。新しい依頼として §8 の照合に従う。
- 照合が済むまでは作業に着手しない。差・未取得・§2 の確認事項があれば、この応答では読み取りだけを行い、ファイル編集・コマンド実行による変更・外部送信・NextAction の更新をしない。
- 確認は会話中の文章で選択肢を示す。ユーザーが回答前にモデル・エフォートを切り替えられるよう、入力を占有する質問ダイアログ(Claude Code の AskUserQuestion 等)は使わない。

## 手順

1. `NextAction.md` を読む(固有層に代替指定があればそのファイル)。無ければその旨を伝え、何を再開するかを質問して終える。
2. 「Next Actions」「保留・未決」「決定済み事項の承認範囲」から次の作業を1つ選ぶ。提案に必要な場合だけ、参照先の設計書・記録の該当箇所を読む(全読みしない)。`git status` で未コミットの変更を確認し、作業と関係するものだけ挙げる。
3. 次の作業に必要なユーザーの確認・判断を洗い出す。承認済みの範囲は再確認しない(§2)。推奨と現在のモデル名・エフォートをそれぞれ照合し、一方でも未取得なら一致とみなさない。
4. 両方が完全一致し、確認事項がなければ、推奨と次の作業を短く示して着手する。それ以外は下の「出力」の形で提示し、ユーザーの回答を待って応答を終える。

## 出力

次の見出しで、簡潔に示す。

- **現在地**: NextAction の要点を2〜3行。
- **次にやる作業**: 作業名・目的・完了条件・主な手順(3〜5行)。対象ファイル・操作の範囲と、既に承認済みの根拠。
- **推奨モデル / エフォート**: §8 に従い1行+理由。現在値も示し、取得できない値は「未取得」とする。実際のアプリで選べる候補から推奨し、未確認なら条件付きと明記する。作業規模(軽い/中程度/重い)と、取得できれば利用残量(取得できなければ「未取得」)。
- **確認事項**: 設定差・未取得には「A: 推奨設定へ切り替えて着手 / B: 現在の設定で着手 / C: 別の作業を指定」を示す。§2 の判断があれば番号を分け、推奨を先頭に各案の利点・注意点と許可範囲を示す。
- **回答のしかた**: 「必要ならモデル・エフォートを切り替えてから、記号で回答してください」と1行添える。

## モデル推奨と利用残量

推奨・現在値・利用残量の判断には `AGENTS.md` §8 を使う。出所の区別、推奨の起点、残量の警告など詳細が必要なら [references/model-and-usage.md](references/model-and-usage.md) を読む。新しい依頼で §8 の予定を示すときも同じ詳細に従う。

## 回答を受けた後

1. 回答を承認範囲として扱い、無回答の質問を承認とみなさない。回答にない範囲や新たな判断が出たら、§2 に従ってその部分だけ選択式で確認する。
2. 実際のモデル・エフォートが確認できれば推奨との違いを1行で伝える(違っても回答を優先し、同じ作業で照合を繰り返さない)。確認できなければ「未取得」とし、切替済みと推測しない。
3. 回答で決まった判断は §1 の節目として `nextaction-update` に従い記録し、作業に入る。
