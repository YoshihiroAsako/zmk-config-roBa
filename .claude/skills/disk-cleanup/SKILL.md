# disk-cleanup

経緯と判断: `../ai-workspace-rules/docs/design/20261120-disk-cleanup.md`(原本では `docs/design/20261120-disk-cleanup.md`)。

## 時期

- 月1回(前回の整理から30日)。予定は `ai-workspace-rules` の `NextAction.md` にある。前回の日付と結果は同じリポジトリの `Archive.md` の「容量の整理」の項。
- 空きが15GBを切ったと分かったとき(Claude Code では会話の開始時に `[容量]` で始まるお知らせが出る。ほかにも、組み立て・インストールが容量不足で失敗した、本人が言った)。気づいたら、作業の区切りで本スキルによる整理を提案する。
- 容量は PC 全体の問題なので、どのリポジトリで使っても、GitHub フォルダ全体と PC 全体の両方を見る。

## 前提(安全)

- **削除は、毎回、対象を一覧で示して本人の承認を得てから行う**(2026-11-20 の本人の選択 R1)。前回承認した種類でも、承認なしに消さない。承認の回答に無いものは消さない。
- 調査は読み取りだけ。調査のために何かを消したり、アプリを止めたりしない。
- 次は候補にしない: Git の対象のファイル(`git check-ignore` で対象外と確かめられないもの)、未コミットの変更があるリポジトリ・worktree、手元のデータベース・設定・ログ・確認写真、AI の会話記録(`~/.claude/projects`・`~/.codex/sessions` 等。監査で使う)、ダウンロード・デスクトップ・ドキュメントの本人のファイル、インストール済みのアプリ本体・ツールの本体(Rust・Node・Playwright のブラウザ等)。
- 直近36時間以内に更新されたものは作業中の可能性があるため候補から外す(`survey.py` の RECENT)。
- Office: 開いている文書・アプリは閉じない。Office 関係の名前の一時ファイルは消さない。Office を操作する必要が出たら、先に `../ai-workspace-rules/docs/office-safety.md` を読む。
- 動いているプログラムが使っているフォルダ(開発用サーバー等)は消さない。迷ったら候補の注記に書いて本人に選んでもらう。

## 手順

1. **空きを測り、候補を出す。** リポジトリ直下で実行する(スクリプトは本スキルのフォルダの `scripts/survey.py`。配布先では `.claude/skills/disk-cleanup/scripts/survey.py`)。
   `python -I <スキルのフォルダ>/scripts/survey.py --root .. --pc`
   出力の区分: CANDIDATE(候補)/ CHECK(要確認)/ RECENT(作業中の可能性。外す)/ TRACKED(Git の対象。外す)/ INFO(参考。外す)。
2. **要確認を確かめる。**
   - `dist`・`build`・`out`: 作り直せる手順(ビルドのコマンド)があるか、公開・提出物として手で置いたものでないかを確かめる。
   - GitHub フォルダ直下の Git 管理外のフォルダ(作業用の写し等): 元のリポジトリを特定し、写しの全ファイルの中身(`git hash-object`)が元のリポジトリの履歴(`git rev-list --all --objects`)にあるかを照合する。履歴に無いファイルは、元のリポジトリの同じ場所と同一かを確かめる。どちらにも無いものが1件でもあれば候補にしない。
   - ごみ箱・Claude デスクトップの Cowork 用の仮想環境(`vm_bundles`。使うときに再ダウンロードされる見込み、中に作業データがある): 本人が選ぶ追加候補にする。
3. **一覧を示して承認を得る。** 非エンジニアにも分かる言葉で、案ごとの箇条書きにする(表にしない)。
   - A(推奨): 作り直せる・再ダウンロードできるもの。項目ごとに、何か・容量・消した後に起きること(次回の組み立てに時間がかかる、部品の入れ直しが要る等)。
   - B1, B2…: 本人が選ぶ追加候補(ごみ箱、しばらく使っていないリポジトリの部品フォルダ、写しフォルダ等)。
   - 残すもの: 大きいが消さないものと理由。
   - 合計の見込みと、回答の例(「A+B2」)。
4. **承認されたものだけ消す。** 消す直前に、対象のフォルダを使っているプログラムが無いかを確かめる(コマンドラインにパスを含むプロセス)。消し方:
   - ダウンロードの控えは各ツールのコマンド: `npm cache clean --force`、`uv cache clean`、`pip cache purge`。
   - Rust の `target` は `debug`・`release` だけを消し、ほかのフォルダ(ダウンロードした部品等)は残す。
   - それ以外はフォルダごと削除する。使用中で消せないものは飛ばし、件数を報告する(無理に消さない・プロセスを止めない)。
   - 一時フォルダは、36時間以上前の項目だけ。AI の作業用フォルダ(`Temp\claude` 等)は消さない。
5. **空きを測り直し、記録する。** `ai-workspace-rules/Archive.md` に「容量の整理」の項を足す(日付、削除前後の空き、消したもの、残したもの、消せなかったもの)。`ai-workspace-rules/NextAction.md` の定期項目の次回の日付を30日後に更新する。他のリポジトリから使ったときも記録先は同じ(複数リポジトリにまたがる作業の記録先。GitHub フォルダの `AGENTS.md`)。
6. **報告する。** 空きの増加、消せなかったもの、消したことで次回の作業に要るもの(部品の入れ直しのコマンド等)を書く。

## 部品を消したリポジトリで次に作業するとき

- `node_modules` が無い: そのリポジトリの手順(README・固有層の「検証」)にある入れ直しのコマンド(`npm ci` 等)を先に実行する。
- `.venv` が無い: そのリポジトリの手順で作り直す(`uv sync` 等)。
- `.next`・`target\debug`: 次の起動・組み立てで自動で作られる(初回は時間がかかる)。
