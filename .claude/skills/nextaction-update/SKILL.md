# nextaction-update

正本は各リポジトリの `AGENTS.md` §1(NextAction.md の運用)。矛盾したらそちらが優先する。このファイルは §1 の手順をチェックリスト化したもので、条文の複製ではない。

## 前提

- AGENTS.md §1 の節目、またはユーザーの明示更新指示で使う。同じ応答内の変更をまとめ、保存する状態変化がなければ終了する。
- リポジトリ固有層で状態ファイルの正が別途指定されている場合は、そちらを対象とする。
- 読取専用・書込み禁止・更新しないというユーザー指示を優先し、委譲された作業の書込み範囲を越えない。該当する場合はファイルを変更せず、結果を依頼元に返す。
- 状態ファイル内の旧テンプレートの注記(自発更新の禁止・追記限定など)が §1 と競合したら、§1 を優先する。ユーザーの個別指示と固有層の明示的な例外は維持し、競合と適用したルールを報告する。

## 手順

1. 現在の状態ファイルを確認する。読込済み内容を利用しつつ、更新する部分の最新内容と差分を照合する。ファイルがなく継続作業の記録が必要なら、代替指定がないことを確かめて4部構成で作成する。
2. 当該作業の完了・検証・決定・承認・却下・問題の変化と、保存すべき履歴を整理する。他作業の変更は保つ。未承認の提案を承認済みにせず、未検証を完了として書かない。
3. **先に履歴を保存する。** 完了事項、解決済み・失効・却下確定の項目を、通常 `Archive.md` へ `## YYYY-MM-DD: (件名)` + 本文で末尾追記する。初回の履歴でファイルがなければ作成する。NextAction から整理する記述は原文と決着内容を保存し、既に同じ内容が保存済みなら重複追記しない。既存の履歴は変更しない。
4. 保存された本文と差分を確認してから、現在地 / 決定済み事項 / Next Actions / 保留・未決 を現状へ更新する。有効な制約・承認範囲は残す。決定・未決も、履歴を確保した解決済み項目は整理できる。却下確定は履歴、再検討条件がある案は条件と判断者を添えて保留へ置く。関係のない過去の全項目を一括整理しない。
5. 完了・決定の担当モデル・エフォートの実績は、Archive の該当エントリにタスク単位で1行記録する(NextAction には書かなくてよい)。確認できた値だけ使い、不明なら「未取得」。推奨値を実績にしない。
6. 未承認の作業が着手可になっていないこと、履歴が保存済みであること、他作業の変更が保たれていることを差分で確認し、更新要点を1行で報告する。書込みできなければ未保存の内容をチャットに示す。

## 分量の上限と棚卸し

- 目安: 現在地は10行以内、決定済み事項は今も効いている決定・制約・承認範囲だけ(1項目1〜2行)、全体で約 8,000 字。
- 全体が目安を超えていたら、今回の更新とは別に、棚卸し案を報告で提案する。案には、Archive へ移す項目、要約して残す制約、そのまま残す項目を一覧で示す。
- 棚卸しはユーザーの承認を受けてから行う。手順3〜4と同じく、先に原文を Archive へ保存して確かめ、今も効いている制約・承認範囲・再検討条件は失わないように要約して残す。

## 共通層候補(教訓の受け皿)

- 作業中に、このリポジトリに限らず共通ルール(`AGENTS.md` 共通層)や配布スキルを直すべきだと分かったら、その場で共通層を直さず、「保留・未決」に1行書く: `- YYYY-MM-DD: 共通層候補: (現象) / (直す先の条・スキル) / (根拠のファイル・場面)`。
- 根拠のない推測は書かない。同じ候補が既にあれば日付と根拠だけ足す。
- `ai-workspace-rules` の定期監査が候補を集めて採否を決める。採否が決まったら、手順3〜4で Archive へ移す。

## 新チャットへの引継ぎ

新チャットへの移行を提案する場合は [references/handoff.md](references/handoff.md) を読み、状態保存と、実値を埋めた再開プロンプトの提示まで行う。強制終了・通信切断時の自動保存は保証しない。
