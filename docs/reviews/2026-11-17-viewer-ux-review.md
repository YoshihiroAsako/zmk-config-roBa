## 結論

優先すべきは、変更を失わない保存操作、変更後のキーボード図、編集を主役にした画面配置。キー選択、実キー入力、コンボの図上選択、Undo/Redo、バックアップは既にあるため、それらを見つけやすく一貫して使えるようにする効果が大きい。新機能はその後に、キーのコピー・交換、マクロの並べ替えを小さく追加するのがよい。

以下のレビュー本文は2026-11-17の提案時点の記録。その時点ではすべて未承認で、実装・キーマップ・ファームウェアは変更していない。その後の具体的な依頼に基づく案 B（UX-03・UX-07）の実装・検証結果を末尾に追記した。Studio RPC / Studio 代替アプリの凍結方針は維持する。

## 改善候補

### UX-01：下書き保護と保存操作の整理【最優先】

**観測・根拠**

- `Reload source` は確認を出さず、追加済み下書きを消す。Q→A の下書きが `1 draft` から `0 drafts` になることを画面で確認。`App.jsx:329` 付近の `reloadKeymapSource` が `setPendingChanges([])` を実行する。
- `App.jsx:384` 付近の `saveSelectedBinding` は選択キーのみ保存した後、全下書きを `setPendingChanges([])` で消す。他キーやコンボの下書きがある場合、それらが保存されず消える処理になっている。これはコード確認であり、ディスクへの保存による再現はしていない。
- 入力中の値と追加済み下書きは別管理。キー選択後の `useEffect` (`App.jsx:212` 付近) は入力値を再設定する。`Ctrl+S` は追加済み下書きの保存だけを呼ぶため、入力しただけの変更は保存対象にならない。
- ブラウザ終了時の未保存警告や再起動後の下書き復旧は実装されていない。

**提案**: 通常操作を「変更を追加 → 変更を確認 → ローカルへ保存」に統一。単一キー保存を残す場合は他の下書きを保持する。未追加の入力も未保存状態に含め、キー移動・再読み込み・タブ終了時に扱いを明確にする。次段階としてローカルへの下書き自動退避と復旧を追加する。復旧時は元ファイルとの一致を確かめ、古い位置情報をそのまま適用しない。

**効果**: 保存漏れと意図しない下書き消失を減らせる。**注意点**: キー・コンボ・マクロ等に共通する状態管理を扱うため、単なる確認ダイアログの追加で終わらせない。

**受入確認**: 他キーの下書きがある状態で単一キー保存しても残ること、未追加の入力が保存対象か画面で判別できること、再読み込みを中止すると入力が残ること、Undo/Redo が保存・再読み込み後の状態と整合すること。

推奨モデル / エフォート / 大きさ: gpt-6-astra / high / 中程度。複数の編集・保存経路を整合させるため。

### UX-02：保存前の変更をキーボード図へ反映【優先度高】

**観測・根拠**: Q→A を入力し下書きへ追加しても、図は Q のままだった。`App.jsx:1041` 付近で `KeyboardSvg` に保存済みの `currentLayer.bindings` を渡しており、下書きは図に使われていない。未追加の編集がある段階でも上部は `0 drafts` と表示される。

**提案**: 「編集中の配置」を初期表示にし、変更キーへ印と `Q → A` の説明を付ける。「保存済みの配置」と切り替え可能にする。未追加の入力・追加済み変更・保存済みを文字でも区別する。全ソースより先に、人が読める変更一覧を表示する。

**効果**: 複数キーの配置変更を保存前に見比べられる。**注意点**: 不正な入力では最後の有効な図を維持し、どの変更が反映されていないか示す。実機の現在状態と誤解させない。

**受入確認**: 複数レイヤーの変更、Undo/Redo、変更の削除が図と一覧に一致し、保存済み表示へ戻せること。

推奨モデル / エフォート / 大きさ: gpt-6-astra / high / 中程度。図・入力・下書きの整合が必要なため。

### UX-03：編集を先頭に置く画面構成と日本語表記【優先度高】

**観測・根拠**

- ヘッダーの `Read-only MVP`、編集欄の `Phase 2 Preview` / `preview only` が現在の保存機能と矛盾する (`App.jsx:982`, `App.jsx:1204`)。
- 右欄はレイヤー名変更、ソース位置、種類などが先にあり、キー選択・保存操作が下に隠れる。マクロ選択時にも通常キーの情報が上に残る。
- `styles.css:17` の最小幅と `styles.css:155` の三列固定構成、下部 270px 固定枠により、小画面では編集欄へ横スクロールが必要。大画面でも小さな文字と複数のスクロール領域が残る。

**提案**: 右欄を「選択中のキー／コンボ／マクロの編集」に切り替え、入力・選択ボタンを最上段へ。ソース位置・compatible 等は「詳細」に折りたたむ。レイヤー改名はレイヤーのメニューへ移す。主操作を「キーを選ぶ」「変更に追加」「ローカルへ保存」に揃え、KP / LT / MT には日本語の意味を併記する。画面幅に応じてレイヤー一覧を縮め、編集欄を下段へ配置。下部の一覧・差分は開閉または高さ変更を可能にする。

**デザイン方針**: 現在の白＋青緑を活かし、主要操作・選択中・未保存・エラーの役割を統一。通常本文は 14〜16px を候補として実画面で調整する。新しい配色や装飾より、情報の順番・文字の読みやすさ・操作の到達性を優先する。

**効果**: 日常操作のスクロールと専門知識への依存が減る。**注意点**: 詳細なソース編集の入口は残す。キーボード図は二次元配置を保ち、周辺フォームを幅に合わせる。[W3C のリフロー解説](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)も、図などの二次元配置と周辺コンテンツを区別している。

**受入確認**: 1280×720、狭いウィンドウ、拡大表示で主操作へ到達できること。キー／コンボ／マクロ選択時に対応する編集欄が先頭に出ること。

推奨モデル / エフォート / 大きさ: gpt-6-astra / high / 中程度。既存機能を維持しながら情報配置を変えるため。

### UX-04：保存後の「実機へ反映する」案内【優先度中】

**観測・根拠**: 保存結果は `Saved .keymap` とバックアップの説明が中心 (`App.jsx:422`, `App.jsx:529`)。実機へ反映するには別の複数工程が必要で、詳細は `docs/viewer-to-device-guide.md` にある。`Studio direct` はこのアプリから実機へ直接反映できるようにも読める。

**提案**: 保存結果に「ローカル保存済み。実機の状態は取得していません」と明記し、既存手順書に沿う「変更を確認 → Git へ反映 → ビルド結果確認 → 左右へ書き込み」の案内を出す。左右は同一ビルドを使うことを表示。自動実行や接続状態の推測は行わない。

**効果**: 保存したのに実機が変わらないという混乱を減らせる。**注意点**: 実機未反映と断定できる範囲を超えて状態を推測しない。Git 操作・公開・書き込みの自動化は今回の候補に含めない。

推奨モデル / エフォート / 大きさ: gpt-6.1-sol / medium / 軽い。既存手順を画面へ案内する変更が中心のため。

### UX-05：キーのコピー・貼り付け・交換【追加機能候補】

**根拠**: 現在はキーごとに入力・選択する方式で、コピー・交換の専用操作はない。検索は既に全レイヤーを対象にできるため、全体検索の新設は不要 (`BindingsTable`)。

**提案**: キーのメニューに「割り当てをコピー」「ここへ貼り付け」「選択したキーと交換」を追加する。最初は同一レイヤーの二つのキーに絞り、変更一覧と Undo にまとめて登録する。

**効果**: 配置を試し直す操作が短くなる。**注意点**: ドラッグ操作だけにせずボタンでも行えるようにする。レイヤー全体の複製・追加は別の判断とする。

推奨モデル / エフォート / 大きさ: gpt-6.1-sol / high / 中程度。複数キーの変更と取り消しを一つの操作として扱うため。

### UX-06：コンボ・マクロの構成を視覚的に編集【追加機能候補】

**根拠**: コンボは既に図上クリックでキーを選べるが、対象レイヤーは番号の文字入力 (`App.jsx:1497`)。マクロには行追加・削除があるが並べ替え・複製がない (`App.jsx:1786` 付近)。既存のパラメーター付きマクロには編集非対応の行も含まれる。

**提案**: コンボの対象レイヤーを名前付きチェックボックスへ変更。マクロには「上へ／下へ」「行を複製」と操作順の日本語説明を追加。高度なマクロは対応範囲を明示し、非対応の制御行の順序を壊さない。テンプレートはこの基本操作が安定した後に需要を確認する。

**効果**: 番号や記法を覚えずに設定しやすくなる。**注意点**: パラメーター転送等を単純なキー列として処理しない。既存のスコープ外センサー動作は追加しない。

推奨モデル / エフォート / 大きさ: gpt-6-astra / high / 中程度。高度なマクロの意味を維持する必要があるため。

### UX-07：キーボードだけで操作できるようにする【画面改善と併行】

**根拠**: キーボード図の各キーはクリック処理を持つ SVG の `g` 要素で、フォーカス・キー操作がない (`App.jsx:1951`)。一覧もクリックする行が中心。キー選択ダイアログは Escape 対応と初期フォーカスがある一方、フォーカスを内部に留める処理と閉じた後の復帰がない (`App.jsx:2734`)。これらはコード確認で、読み上げソフトでの検証は未実施。

**提案**: 図・一覧をキー操作で選択可能にし、選択位置を見える枠で示す。ダイアログ内で Tab が循環し、閉じると元のボタンへ戻るようにする。保存・エラーを読み上げ可能な通知にする。ダイアログの操作は [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) を基準に確認する。

**効果**: マウスを使わない編集がしやすくなる。**注意点**: Capture 中と通常のショートカットの役割を分ける。属性追加だけで完了としない。

推奨モデル / エフォート / 大きさ: gpt-6.1-sol / high / 中程度。フォーカス移動と既存ショートカットの整合確認が必要なため。
