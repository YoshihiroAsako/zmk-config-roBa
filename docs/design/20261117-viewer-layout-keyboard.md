## 選択肢と比較

- 採用: 通常のページスクロールを基本に、広い画面は3列、狭い画面は図の下へ編集欄を置く。フォームを先頭、ソース情報は details に格納する。図の二次元配置は維持する。
- 不採用: 固定高さの3列を維持し、個別スクロールだけで対応する案。拡大時の到達性と操作領域の分かりにくさが残る。

## 推奨案・判断

- 編集対象と下部の表示タブを区別し、変更一覧へ切り替えても選択対象の編集欄を維持する。保存・下書きの意味や処理は変更しない。
- レイヤー改名はレイヤー欄の折りたたみへ移す。下部一覧は開閉可能にする。
- 図はフォーカス可能なボタンとして扱い、矢印で移動、Enter/Space で選択する。一覧は各行に通常の選択ボタンを設ける。編集欄への移動リンクを用意する。
- キー選択はネイティブ dialog の showModal で背景操作を止め、Tab/Shift+Tab の端で循環させる。Escape・確定・閉じる操作後は呼出元へ戻す。表示項目が切り替わる場合と Capture・通常ショートカットの競合も確認する。
- 保存結果を共通の通知領域へ置き、選択対象・フォーカス・入力エラーを文字と枠で判別可能にする。
- 新規依存なし。UX-01/02/04/05/06、Studio 代替計画、Task G/H は対象外。
- 他 AI レビュー: 不要（保存形式・API・承認済み方針の変更なし）。
