- 承認判断: 案 A の設計・ローカル実装・検証・状態記録は依頼済み。commit・push は別指示。

## 背景

再読み込みと保存が追加済み変更を一律に初期化する一方、履歴が保持するパッチの位置は旧ファイルを参照し続ける。入力欄も保存済みデータから再初期化される。図には保存済みの配列だけが渡され、適用・検証したパッチが使われていない。

## 使い方の確認

- roBa 利用者が、キーや関連設定を編集した直後に「編集中」と「ローカル保存済み」を見比べる。
- 「変更に追加」で一括保存の対象にする。Ctrl+S と一括保存ボタンは同じ対象。単一キー保存では選択キーの有効な入力だけを保存する。ほかの入力・追加済み変更は保持する。
- 実データの構成は 7 レイヤー、各 43 キー、5 コンボ、1 マクロ。
- 本人が試用できる最小単位は、1 キー入力して図の比較を行い、追加または単一キー保存する流れ。指定済みのローカル実装と検証を先行する。

## 選択肢と比較

- A: 追加済みパッチと入力値を分け、検証済みソースから図を作る。既存の一括・単一保存を維持できる。保存後の位置補正が必要。
- B: 単一保存を廃止し、保存時に画面全体を初期化する。履歴の境界は単純になる。単一キー保存の要件を満たせず、各入力の保持も別途必要。

## 推奨案

案 A。キー・レイヤー・コンボ・マクロの選択変更は、消える未追加入力がある場合に確認する。明示的な再読み込みと復元は、成功時にだけ入力・下書き・履歴を消す。タブ終了やブラウザ再読み込みはブラウザ標準の警告を使う。

単一キー保存後は他のパッチと履歴の文字位置を補正し、保存したキーを履歴から外す。一括保存後は履歴を初期化する。ファイルの内容が画面の正本と変わっていれば保存を止め、位置がずれた状態での上書きを防ぐ。

図は検証済みの追加済み変更に、有効な未追加入力を重ねる。入力が不正なら理由を通知し、同じ保存済みファイル・追加済み変更・選択の組み合わせで直前に確認できた配置を表示する。それがなければ追加済みまたは保存済みの配置を表示する。コンボ対象と、マクロを直接またはコンボ経由で参照するキーにも変更を表示する。

## 影響範囲

- `src/App.jsx` / `src/styles.css` — 編集値・保存・履歴の制御と、配置・状態表示を更新。

- 保存形式、依存定義、実機運用は従来の構成を維持。既存保存 API に任意の照合値を追加する。
